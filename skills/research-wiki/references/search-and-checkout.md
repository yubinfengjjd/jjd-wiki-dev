# 统一检索与资产获取

默认 `rwiki find "自然语言问题" --json` 检索知识页的章节正文，包含方法、模板、配方、场景、接口、图型、课题和图样；章节命中合并到页面。英文缩写按词边界匹配，中英文术语和中文二字片段参与 BM25 排序。来源目录中的 L0 条目可发现，但不因此可执行。归档和作者移除的内容不进入默认结果。

`--scope source` 明确切换到本机已下载的代码与说明；覆盖范围随结果返回，数据矩阵、日志、输出、缓存和二进制不参与检索。不会联网补全未下载材料。`--kind` 精确筛选类型；`--runnable` 在返回前重新核对当前来源、代码和收据。正文、代码和收据变化后不得沿用旧执行资格。

网页 `GET /api/search?q=...&kind=method&scope=knowledge&limit=20&runnable=false` 调用同一核心，GET 不下载、不修改正式知识。静态网页的结果是注明导出时间的快照，不能替代本机执行前的证据核对；静态导出不包含源码范围。

## 两种检出

`tools/get-wiki.ps1 -Destination <父目录> -Profile light|full` 获取同级的两个原名仓库。light 使用部分克隆和稀疏检出，展开知识页、必要声明和缩略图；源码、完整示例、原始画廊与历史档案按需补齐。现有完整检出不会自动缩减。

- `rwiki assets fetch <id>`：获取条目与声明依赖。保留之前已下载内容；网络失败允许重试，不修改验证状态。
- `rwiki use <id> --project <课题目录>`：明确复用时补齐资产，再按既有规则复制到课题。已存在的课题副本不受外层迁移影响。
- `rwiki checkout --profile full`：完整展开后再做正式维护。轻量检出拒绝全库保存、入库确认与状态修改。

资产获取不会自动安装科研依赖。包安装、输入含义及统计逻辑仍遵守作者既有确认规则。检索缓存是外部 work/search 下可重建 JSON，不是知识正文或数据库。
