## 做了什么

前端此前停在 T4 的数据模型（一张整图 = 一个模板）。M3 一次补齐 P1 与 M1/M2 之后的全部页面类型：

- **数据层** `api.ts`：类型改为 layout / template / method / interface 四类加枢纽页；状态加 draft、pending_confirm；写接口统一为 `/api/{layouts|templates|methods}/{id}/…`，新增 confirm、return；graph 边带 `kind`。
- **`flow.ts`**：从 graph 的 feeds 边读“方法 → 接口 → 模板”链。“可接的图”与后端 facts 同一规则（模板所需全部接口都在方法输出中）。
- **导航**：图库（整图版式 / 单图模板两栏）、方法库、知识网络、待办、日志。
- **方法库页**：方法卡片正面是它能画出的图（扇形叠放的模板预览）加输出接口标签；下方数据接口列表（列、产出方法 → 读取模板）。
- **页面**：方法页有“分析 → 出图”链、示例输出前 6 行（读 `example/output/*.csv`）、确认/退回/收藏/归档、场景标签、备注、来源与许可（无许可证标橙色“仅供个人研究参考”）、应引用文献。模板页有可接方法链。接口页有“谁写它，谁读它”。版式页有签核/退回、按版式回放、拆成的单图模板（带面板字母）。
- **待办**：待你签核 / 待你确认 / 等 agent 处理 / 已归档。
- **知识网络**：方法画方块（紫）、接口画菱形（灰蓝）；feeds 边紫色并在屏幕空间画箭头；外圈状态色覆盖图、模板、方法。

## 验证

- `tsc --noEmit` 与 `vite build` 通过。
- 桌面 1440 与手机 390 截图逐页目视；390 宽下无横向溢出（修正了 prose 表格撑宽页面的问题）。
- 浏览器端到端：随机森林方法 pending_confirm → 点“确认可用” → 可用，产生提交 `confirm rf-shap-regression`；两个方法在网页补上场景“模型解释与特征重要性”，各产生提交。之后 `suggest-pipeline --scenario model-explanation-shap` 能找到两个方法；lint OK。

## 审查中自己发现并修正

1. 方法卡片初版把链条横排在 260px 宽的卡片里，接口名被挤成竖排；改为“预览扇形 + 接口标签”上下结构。
2. 小规模 wiki 的网络图自动适配缩放过大（节点像大圆盘）；适配时至少按 280 单位宽取景（`FIT_MIN`）。
3. 场景编辑器与备注编辑器的 React key 在两者都为空时相同（都是空串），保存后旧编辑器残留在页面上；key 加前缀。T5 时模板都有场景标签，没暴露。
