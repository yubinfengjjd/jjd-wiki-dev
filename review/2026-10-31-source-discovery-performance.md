# 来源可发现性与首屏性能修复

FigureYa 的中文模板标题不包含软件名，原图库又不检索 ID 或来源，因而搜索 FigureYa 会漏掉已有的三个 L2 模板。原 UI 没有 L0 浏览入口，来源登记完成后也无法按模块浏览。

现在图库检索来源、ID 和关键词；新增来源目录，区分 L0 目录项、L1 整模块配方和 L2 函数模板，三层都支持搜索。L0 明示未在 Wiki 运行，上游图仅作参考；没有升级状态或新增运行收据。

原首页等待页面列表、全量图谱和方法分类三个接口全部完成才显示内容。`/api/pages` 为 188 个页面调用 6210 次页面读取/解析，每个方法的关联图查询又重复扫描全库。修复后，GET 请求内复用页表与解析，metadata 深拷贝隔离调用者修改，并按文件 stat 检测同请求中的文件变动；请求结束丢弃缓存。写请求不进入该缓存。

首屏先显示轻量目录，条目统一处于“正在核对证据”，保存预览也明确不是当前回放结论；完整证据、图谱与分类独立补全。后续请求仍核对当前证据，没有跨请求缓存可用性。过期加载结果不能覆盖当前目录或证据缓存，图谱失败不会抹掉已显示目录。

## 本机测量

同一 Wiki 数据、同一解释器与依赖，顺序 HTTP 测量，非统计分位值：

| 接口 | 原服务 | 候选服务 |
|---|---:|---:|
| 首屏轻量目录 | 无 | 0.968 s |
| 完整页面列表 | 35.045 s | 6.961 s |
| 图谱 | 3.344 s | 1.826 s |
| 分类 | 0.703 s | 0.790 s |
| L0 来源目录 | 无 | 1.001 s |

完整页面响应与保存的原服务 JSON 完全一致。来源接口返回 316 个 L0 条目，全部 `usable=false`。首屏耗时不等于全部证据核对完成耗时。

## 验证范围

- 后端回归先失败后通过：单次请求每页只解析一次；外部编辑下个请求可见；缓存 metadata 不相互污染且 CRLF 原字节不改；轻量接口不调用证据核验、不授予 ready；L0 仅按完整来源身份去重。
- 前端回归覆盖 FigureYa 来源搜索、L0 原图/许可/未运行标记、三层搜索、渐进加载、图谱失败，以及迟到结果不能覆盖当前证据缓存。
- TypeScript 检查、前端模型与 SSR 测试、生产构建通过；完整后端测试结果与 CI/独立评审记录见 PR。
- 浏览器实测：图库搜索 FigureYa 显示三个函数模板；来源目录显示三个 L2、30 个 L1、316 个 L0；切换压缩包来源为 33 个 L0、零个该版本 L1/L2，保留版本差异。
- 仅修改开发仓库与可重建前端；不修改主库作者区块、配方/方法原始层、图像、签核或统计逻辑。
