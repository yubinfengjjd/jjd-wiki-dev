# 科研知识库 · agent 维护规则

这是一个 LLM Wiki。知识以本目录下互链的 Markdown 页面为本体，由 agent 编译和维护，作者阅读、签核、备注。改任何页面前先读完本文件。

它是写给 agent 读的说明书，不是执行平台：页面写清每样东西是什么、什么时候用、需要什么数据、代码怎么改；agent 读懂后在作者当前课题的环境里自己写代码、运行。图模板带可运行代码并经回放验证；分析方法是笔记，可附可复用的代码模板，知识库不运行它们。

## 当前收录范围

复刻与新收录只接受一个逻辑 panel。先识别去重样式，再询问代表单 panel、数据及关键细节并确认计划；完整原图只读保留在画廊用于溯源，不作为 Wiki 条目或复刻交付目标。现有整图来源已归档并在前端隐藏，保留其来源记录及既有单 panel 模板。图库保留“单 panel 图样”和“可调用模板”两个可重叠浏览入口。

## 三层

- **原始层（只读）**：科研绘图画廊（路径见 research-wiki 技能的 `config.json` 里的 `gallery_root`）。每张复刻图是一个条目，`meta.json` 是事实来源。第二版会加入 Zotero、笔记、PDF。不改原始层，签核状态除外（只能通过 `wiki.py` 或网页修改）。
- **wiki 层**：本目录。agent 编译的页面。
- **规则层**：本文件。

## 页面类型

| 目录 | type | 内容 |
|---|---|---|
| `layouts/<id>.md` | layout | 一个逻辑 panel 来源，记录所含模板；历史整图仅保留归档记录。`<id>` 与画廊条目 id 相同，签核状态在这里 |
| `layouts/<id>/` | — | 版式资产：`thumb.png`；可选的版式回放另有 `layout.json`、`example/`、`preview.png`、`verify/` |
| `templates/<id>.md` | template | 一个逻辑 panel 模板，可单独套用。沿用 `<版式 id>--<图型>` id；结构变体默认分属不同代表条目，可被多个版式引用 |
| `templates/<id>/` | — | 模板资产：`spec.json`、`code/`（含 `panel.py`）、`example/`、`preview.png` |
| `methods/<id>.md` | method | 方法笔记（一步分析）：用途、适用/不适用、输入、怎么做、代码、输出成哪个接口、来源与许可证 |
| `methods/<id>/` | — | 方法资产（都可选）：`source/`（原代码归档，只读）、`code/`（可复用代码模板） |
| `interfaces/<slug>.md` | interface | 数据接口：一种标准表格（列名、类型、含义）。方法最后整理成它，模板读取它 |
| `chart-types/<slug>.md` | chart-type | 图型枢纽页 |
| `projects/<slug>.md` | project | 课题页，记录用过哪些模板、成图在哪 |
| `index.md` | — | 脚本生成的目录，不要手改 |
| `log.md` | — | 只追加的操作日志，不要手改 |

链接一律用相对本目录根的双链：`[[templates/<id>|显示名]]`、`[[layouts/<id>]]`、`[[interfaces/shap-summary]]`。frontmatter 里的列表字段（`tags`、`chart_types`、`templates`、`layouts`、`panels`、`inputs`、`outputs`）存的是值，不是链接；来源/互补关系靠正文链接表达；方法—图语义关系在方法侧 figure_relations 唯一维护，反向自动派生。

`tags` 是自由标签（如“模型解释”“SHAP”“原图出自 QSAR”），只帮助检索，不是分类，也不限定用途。一张图或一个方法能用在哪里，写在“适用”节：它回答什么问题、需要什么形状的数据，与学科无关。

## 什么能进知识库

- 版式页只能由 `wiki.py ingest-figure` 根据画廊条目生成；画廊条目只由 sci-figure-replica 复刻产生。panel 模板只能从已签核的版式拆出（`scaffold-template`）或复用（`attach-template`）。不得手工新建这两类页面，也不得为没有复刻过的图写页面。`lint` 会报告找不到画廊条目的版式、来源不明的模板。
- 图型页只在收录复刻图时自动补齐；课题页只由 `record-use` 生成。
- 方法笔记由 agent 用 `scaffold-method` 建骨架后编写，来源可以是帖子代码、作者课题脚本、GitHub/论文代码，或 agent 依据文献与官方文档编写（`--written`，必须写 `cite`）。

## 先咨询样式与范围

输入文章、图或代码时，agent 实际读图后列去重样式卡：代表裁图、原图/bbox 与重复位置、视觉编码、附属结构、已有模板/差异、不确定点。每个选定样式只做一个代表单 panel；模型/指标/单位/颜色变化通常作为参数，编码或结构实质不同才保留可选变体并说明理由。inset、色标、边缘分布和必要共享标注随主 panel，多 axes 不等于多个模板。图片数、哈希或图型名均不能代替样式判断。

在渲染或正式收录前，集中明确选定样式/代表、数据来源、保真重点、语言/代码及交付计划；复用已有答案。缺原始数据先说明缺口及影响，询问作者本次用估读还是合成并等待选择。完整原图/哈希只读保留，选定裁图与原图 bbox 另记；未选 panel 不构成本轮覆盖要求。完整整图只在画廊只读保留作溯源，不再复刻整组或新建整图 Wiki 条目。历史整图来源通过 Wiki API 归档并在前端隐藏，保留历史模板的出处。

方法联想限定为有依据的方法家族推广（如 XGBoost＋SHAP → 满足条件的机器学习模型＋SHAP）：保留原实现，说明适用范围、前提、限制与未实现/未验证分支；不从画法通用性推导宽泛新分析方法。先写文字，有来源代码可按函数契约融入，不自动补算法。

## 谁能改什么

- `<!-- user:start -->` 与 `<!-- user:end -->` 之间是作者的内容。agent 一个字都不改，也不移动。
- `<!-- facts:start -->` 与 `<!-- facts:end -->` 之间由 `wiki.py` 生成，每次收录都会重写。agent 不手改，要改就改原始层后重新收录。
- 其余正文由 agent 负责：可以重写、合并、补链接，保持准确简洁。
- frontmatter 的 `status`、`favorite`、`archived_from` 只通过 `wiki.py` 或网页修改。

## 操作

所有写操作的最后一步都是 `wiki.py save "<说明>"`：重建 index；有变化时追加 log 并 git 提交，没有变化时什么也不做。`ingest-figure` 已经包含这一步。

### 收录（ingest）

1. `wiki.py ingest-figure <entry_id>`：建或更新版式页骨架、补齐图型页、提交。标签从画廊条目带过来。
2. 读画廊条目的 README、`qa_report.md`、`figure_spec.json` 和原帖 `source.md`，核对实际范围：单 panel 的 `source_image` 是选定裁图、`source_image_sha256` 是裁图哈希；完整原图另存并记录独立哈希/bbox。填写版式页的“适用”和“不适用”：所选图样回答什么问题、需要什么数据、什么时候不该用它。写有依据的用途，学科背景可作标签，不据此限定或夸大适用性。新 layout 页只代表一个选定逻辑 panel；收录前核对 panel_map 恰好一项。完整原图不进入新 Wiki 条目。
3. `wiki.py save "ingest <id> 说明"`。

### 收录后的配图、范围与知识关联

新增/实质更新方法或图样后，双向检查“一方法多图／一图多方法”，包括不同来源。核对目的、语义、行单位、量纲、前提与代码状态，有依据才写 figure_relations（方法侧唯一记录）。状态为 direct/adaptable/candidate，分别为直接可接/需要适配/待核实，另写 verification 的状态、范围、证据。来源图样不能 direct；接口 feeds 只表示结构匹配。方法页/图页/图谱从同一记录派生；归档不再推荐，删除清理关系并审计。正文记录检查范围、依据和未关联原因。详见 research-wiki 的 references/knowledge-linking.md。

图库仅按单panel图样、可调用模板两栏区分。新layout只容纳单panel来源；历史整图归档隐藏。逻辑panel数而非axes数决定来源范围。图片、状态和范围都需在前端实查，逐一检查已有单panel函数模板能在图样入口找到。n为任意合法数量，由课题agent编排；文档中的能力标准不代表所有历史模板已经适配。

### 处理待办：拆 panel 与模板化

作者签核后版式变为 pending_template。作者说“处理待办”时：

1. `wiki.py pending` 列出尚需agent处理的来源；先查关联模板，继续已有草稿或补缺口，不重复新建。
2. 按选定样式处理，不按图型名机械合并。一个代表单 panel 一个条目；inset、色标、边缘分布属于该 panel。结构变体默认在不同条目中保留，现有 `<条目 id>--<图型>` id 无需扩展。同条目的历史组图若存在同图型不同结构，不能为适应 id 冲突强合并；记录具体限制再决定最小处理，不自动重做旧图。
3. 先查已有 ready 模板，核对数据接口、编码和附属元素；相同画法用 `attach-template` 复用，实质不同才 `scaffold-template`，写清差异。模型/指标名或颜色变更不自动新增模板。
4. 按下述函数契约处理代码。`code/` 包内相对导入；保留 `panel.py` 的 `draw(fig, rect, tables, style)` 适配，在给定区域作画，可调视觉参数放 spec.style。独立调用、render 和组图共享绘图核心。
5. 每个模板 `verify-template` 单独回放，对照选定裁图检查并交作者确认；确认后 `mark-ready <模板 id>`，即可独立 `render` 并换数据检查。这个链路不依赖 `verify-layout`，来源 layout 此时仍可为 `pending_template`。
6. 若还要将来源 layout 标为 `ready`，须为它准备自己的 `layout.json`、覆盖本条目已选 panel 的布局和 `preview.png`，运行 `verify-layout`，交作者确认后再 `mark-ready <版式 id>`。选定 A 单 panel 时使用只含 A 的 1×1 布局与覆盖，绝不要求未选 B；不再制作整组回放或要求未选 panel。测试或回放不自动推进作者签核。

### 接口

- 接口按数据本身定义，与模型和工具无关：“SHAP 汇总表”是一个接口，不分 XGBoost 还是随机森林。
- 新建前先找已有接口：`scaffold-template` 会打印列名相同的接口，能复用就复用。确需新建时用 `add-interface`，并在“含义”节写清一行代表什么、与相近接口的区别。
- 模板 spec 的每张表只写 `interface` 和 `description`，文件名固定为 `<接口 slug>.csv`。分析函数返回表，显式调用层可将表写成这些文件交 `render`；内存表也可直接传绘图函数。接口相接只是候选条件，仍须检查方法前提。

### 收录方法（写方法笔记）

1. `scaffold-method <id> --title … --license …`，来源选一种：`--from-entry <画廊条目>`（帖子代码）、`--from-path <路径>`（作者课题脚本；GitHub/论文代码加 `--url --commit`，下载前须征得作者同意）、`--written`（依据文献或官方文档编写）。原代码复制到 `source/`，不改。
2. 一个方法页可表达有边界的方法家族；写清核心目的、来源具体实现、成立条件、已有代码分支、限制与未验证分支。按实际数据条件和实现边界说明工具/模型适用性；不能为支持“任意模型”强改算法。预处理与分析分开写；前后接口兼容且方法前提满足时才串联。只有联想而无代码的方法先保留文字，不自动实现。
3. 写正文各节：
   - **用途**：做什么、结果是什么。
   - **适用 / 不适用**：数据前提（样本量、变量类型、任务类型）、什么情况会得出误导结论。
   - **输入**：需要什么数据、每行代表什么、哪些列。
   - **怎么做**：步骤；作者数据不同时要改的地方；方法前提、必要诊断及结果限制，避免无依据的通用判断。
   - **代码**：有来源代码时按下述契约放修改副本进 `code/`，写函数签名、参数含义、依赖、限制和验证状态；没有则明确“文字笔记/未实现”，不强制补代码。包依赖在这里说明，不在知识库里装环境。
   - **输出**：最后怎样整理成哪个接口表（列名、每行含义），frontmatter 的 `outputs` 同步写接口 slug。
   `license` 不明时写 `none`，页面会显示“仅供个人研究参考”；`cite` 只写能核实的文献。
4. 写完交作者确认（网页“确认”或 `mark-ready`），确认后才推荐。

### 有来源代码的函数契约

- 记录原语言、来源/许可证或未知状态、原字节及 SHA-256；源代码只读，函数化修改版独立，列原函数与新入口映射。普通路径/输入输出整理和参数化在已确认计划内可做；改变统计逻辑、估计量、泄漏边界、缺失值/异常值算法，替换或补缺失分析算法前，说明具体差异并询问作者。
- 分析函数显式接受数据对象、变量/结局/分组列、算法实际需要的参数和随机性，返回结构化结果表及必要诊断，记录列/类型/每行含义。默认不隐式读写、绘图、联网、安装或修改知识库；原算法必要副作用明确隔离和记录，不能静默删除。
- 绘图函数消费表，显式列映射与视觉参数，不隐式训练或重做分析。按原语言传入/返回可组合对象：Python 通常为 figure/axes，R 为适合的 plot/grob。边缘分布等多 axes 仍为一个逻辑 panel，导出由显式调用层处理。
- 复制所需模块到作者课题，用课题自己的 Python/R 环境；数据、列和必要参数显式传入，不依赖原工作目录、硬编码路径、知识库目录或全局临时变量。保留 render/draw 适配，共用绘图核心；分析和绘图可独立或串联。不要求制作全局 pip/R 安装包。
- 实际比较原版与封装版数值结果、行顺序、缺失值处理、随机性和图形结构；必要容差说明依据。检查不同工作目录、复制到课题后换数据的可移植性，记录命令/环境/结果。未运行项目标未测，不能把单例通过扩大为任意数据、模型或科学有效性。


### 数据规模适配也是函数化验收的一部分

这里 n 是依据课题既定分组定义从实际数据识别的任意合法组数（正整数），不设固定数量白名单，不为每个 n 写分支或另建模板。agent 在做课题时自行绑定数据、识别 n，并按图型、标签、附属元素和版面要求编排尺寸、留白、配色和位置；每项宽/高等默认系数只是可覆盖初值。不得擅自改变研究分组含义来适应图形。作者已指定的样式/尺寸限制继续遵守；未指定时按既有单panel、可读字号和间距原则执行。

函数化须能适应同类场景的数据结构变化，不只是把原脚本包进函数。分组/类别/系列数量、顺序、标签、配色和位置从显式输入或数据获取；不把原图六组、固定模型名或固定列数写成复用限制。分析函数仍遵守自身算法前提，不为支持更多组而自动改变统计方法。

绘图先声明尺寸驱动：纵向分类图按类别数加宽，横向条形图按条目数增高，矩阵按行列数调整；散点不因样本数增多而无限放大，必要时使用固定比例。规则例如 W=左右留白+n_x×每项宽度、H=上下留白+n_y×每项高度；系数与物理单位由模板说明、参数化，长标签可增加所需空间。字号和最小组间距保持可读，不能靠缩小字体掩盖拥挤。

默认保持一个逻辑panel、保留间距并继续加宽/增高；max_width_in/max_height_in默认null。只有作者明确设置尺寸上限，才在超限时报告所需/允许尺寸并询问方案，不自动截断、压缩、分面或隐藏类别。布局须同时检查标签/图例/色标及配色是否足够；不得对离散组静默循环有限色板。

原图复刻用replica/fixed模式保留显式宽高及原图比例；换数据用adaptive模式，验收宽高增长、间距和文字，不拿原图宽高比阈值约束自适应复用。调用方可显式覆盖参数。组图draw(fig,rect,tables,style)尊重外层画布，不能自行resize；空间不足应交调用层扩大布局或询问作者。

新Python模板的spec.style.sizing从research-wiki config.json的function_defaults.sizing快照，随code/sizing.py复制到课题；配置优先级为调用覆盖>模板快照>建模板时的全局默认。默认profile=unbound，agent必须确认实际表/列和方向后绑定，不凭图型名猜数据含义。函数与render共用同一尺寸/绘图核心，输出解析后的尺寸记录。Python实现及完整例子见research-wiki的references/adaptive-sizing.md；R保留原语言并实现同等行为，不能把Python验证写成R已验证。

验收覆盖代表规模变化：由agent按模板和课题选择若干不同组数及适当边界案例，另测不同样本数、长标签、显式顺序/列映射、配色不足处理、手动尺寸与用户上限；横向图/矩阵检查相应维度增长。比较数值和行序不变、无输入修改、图形数量正确、物理组间距不缩小、文字无裁切；复制到另一目录换数据实际运行，独立入口和render/组合入口分别记录。仅测试原图规模不算完成规模适配。历史模板逐一记录legacy/适配状态，不因新规则自动宣称已迁移或批量改历史图。

### 查询与推荐（query）

1. 先读当前课题必要计划、数据说明、代码、结果表头与运行证据，明确研究目的、样本/行单位、验证设计、当前阶段及未知项。代码存在不证明已跑完；缺目的或关键条件先问作者。不由网页服务器扫描任意课题目录。
2. “课题还能做什么分析”：用 suggest-methods 查 ready 方法，不限是否已有配图；优先少量当前可做项，再给少量有价值且能说明缺哪些材料的候选。说明用途、项目依据、前提、缺口、代码存在/验证范围、可配图样。无合适库存就如实说明。
3. “分析已跑完选图”：先核对结果语义/粒度/量纲/重复层级，再 suggest 查单 panel/模板；不必新增方法。接口/列名不同不能是发现的唯一排除条件，同名也不证明直接适用。suggest-pipeline 结合关系提供候选，agent 仍须读正文。同一张图有多种可接方法时，列对比（各自适用什么数据、作者数据是否满足）并给出首选与理由，由作者决定。
4. 有现成选择与计划就复用，否则等作者选定。含义清楚且不改分析逻辑时，课题副本可映射列名、列顺序、文件名和长宽表；原表不改，继续通过执行入口的严格检查。核对源哈希、主键、值、实体、单位与转换可还原；不能要求长宽转换总行数相同。
5. 未知单位/指标定义、重复身份不清、缺关键材料，或涉及聚合/删行/填补/补样本/重算统计量/单位换算/阈值或验证设计改变，说明具体差异先问作者。缺包也先问，不在 Wiki 装包或换 Wiki 环境代跑课题。
6. 选定后复制代码到课题，用课题环境运行、检查前提/诊断、出图并 record-use。无算法的文字笔记不授权补算法。方法/图关联直接可接不证明当前课题统计有效。
7. 复用课题已有记录；无约定则用 <课题>/wiki-use/<本次标识>/ 记录 context、recommendations、mapping、实际调用与检查。项目映射先留课题；有通用价值时提出回存内容和证据，作者再次确认才入库，不覆盖原版或污染全库接口。详细模板见 research-wiki 的 references/project-reuse.md。

### 原生代码与网页查看

原生 source/ 与复用 code/ 分开，语言/字节/来源/许可证/哈希保留；原文片段不能标成完整原版。方法、单 panel 图样、模板卡片的“查看代码”在 Wiki 内显示版本和文件，支持复制/下载，仅只读查看。未知编码或二进制原字节下载，不运行网页代码或 Notebook 输出，不增独立代码分类。枚举真实文件，无代码如实说明。代码存在、页面 ready、关系兼容与实际验证范围独立。详见 research-wiki 的 references/code-assets.md。

### 体检（lint）

`wiki.py lint` 报告断链、frontmatter 不合规、页面与画廊状态不一致、空白的适用说明。逐条修复（能改页面的改页面；属于原始层的问题报告给作者），然后 `save`。


### 归档条目的删除与预览

网页归档区和详情可先查看删除范围，再由作者明确确认永久删除 Wiki 页面及其专属资产；自动清理 agent 正文、元数据与布局中的关联，记录到 deletion-records，原始画廊保留。操作不可从网页恢复，Git 历史不作清除。后端仅允许 archived 状态，并核对确认时的内容版本；他页作者备注引用须由作者先处理，不能自动改备注。agent 不因作者要求“加删除功能”就代删正式条目。

预览以实际存在的资源为准。模板没有回放图时可显示对应单 panel 来源缩略图，明确标“来源参考图 · 模板尚无回放”；没有可用图时显示暂无预览，不请求不存在的 preview.png，不以来源图冒充已验证模板。

| status | 含义 | 谁来推进 |
|---|---|---|

| archived | 已归档，不再推荐；`archived_from` 记录原状态 | 作者在网页恢复 |

panel 模板：

| status | 含义 | 谁来推进 |
|---|---|---|
| draft | 已拆出，代码与回放待完成或待作者确认 | agent 回放，作者确认后 `mark-ready` |
| ready | 可单独套用 | — |
| archived | 已归档 | 作者在网页恢复 |

分析方法：

| status | 含义 | 谁来推进 |
|---|---|---|
| draft | 笔记待完成或待作者确认；或被作者退回（log 有理由） | agent 写完后作者在网页确认或 `mark-ready` |
| ready | 可推荐 | — |
| archived | 已归档 | 作者在网页恢复 |

## 写作要求

- 页面写给作者和下一个 agent 看：事实优先，短句，不写套话。
- 不编造数据、文献或适用结论。不确定就写“待作者确认”。
- 不复制原始层的大段内容，链接或引用路径即可。


### 待办按剩余动作派生（CLI 与前端共用）

持久 status 表示来源签核/版式回放或模板确认阶段，不等于当前谁还有工作。后端只读 workflow 统一判断：

- 已签核来源尚缺有效模板覆盖：agent核查缺口、归档或关联，保留已完成部分。
- 已有草稿但无完整成功回放：agent继续该模板，不重复scaffold；来源不重复算一项。
- 草稿已有成功回放记录和对应输出：交作者确认，列入“待你确认”，不列agent待办；代码改变后仍应重新verify-template并核对回放，文件存在不证明科学有效。
- 所选panel已由ready模板完整覆盖：来源显示“模板已就绪”并退出待办，即使其status仍为pending_template。来源可选layout回放与单模板可用性分别记录。
- 待签核来源/新版本仍交作者签核；回放不自动确认。归档/删除模板导致覆盖缺失时重新派生待办，恢复后重算。

`pending`只列尚需agent处理的来源ID（包括已有未完成草稿）；先检查关联模板与当前说明，不见pending_template就重新拆模板。重复ingest或刷新不会新建待办记录或推进状态。不得为了清零而伪造layout验证、作者确认或删除来源。


### 入库与展示验收

新收录或实质更新的知识按以下标准检查；未完成项明确列出，不以入库、代码存在或页面ready代替实际验收。历史单panel模板可以保留，注明历史来源与尚未迁移的能力，不据新标准伪造已完成记录。

| 检查项 | 验收要求 |
|---|---|
| 来源与范围 | 新图样只记录已选定的一个逻辑panel；裁图、完整原图/bbox、数据及代码来源可追溯，估读/合成标注清楚。原图与原生代码只读，关键选择复用作者已给答案。 |
| 图样去重 | 模型/指标/颜色/组数变化不机械新增样式。方法配图只在明示的来源与模板覆盖关系成立时合并视觉入口，保留所有语义关系及来源链接；不同结构变体和不同方法不得因图型同名而误合并。 |
| 两栏数量 | 单panel图样按逻辑图形样式浏览，包含已有单panel函数模板；可调用模板按函数入口浏览，同一记录可同时出现在两栏。图样依据明示来源覆盖去重，不能按页面存储类型把模板排除。历史整图来源归档只隐藏整图，不隐藏已拆出的单panel图样；保留出处与能力限制，不新增伪来源或待办。两栏允许一对多、多对一，数量不要求强行相等。 |
| 方法家族 | 写清用途、原始具体实现、可推广范围、适用/不适用、输入、输出、代码与未验证分支。原实现保留，方法联想有依据；一方法多图/一图多方法双向检查，不能从通用画法推出无边界的新分析。 |
| 数据与关系 | 按语义、行单位、量纲、配对和研究前提判断。列名/长宽表不一致可在课题副本适配；缺数据或改变统计逻辑先问。关系direct/adaptable/candidate与运行验证分别记录；需适配的图明确写数据来自何处、还缺何种准备，不制造直通流水线。 |
| 代码资产 | 有原生代码则保持原语言与原字节/哈希，原始版/复用版可区分；卡片查看代码真实可用，可复制/下载。无代码的方法如实标文字笔记，不补算法凑齐。绘图与分析分离，函数可复制到课题，任意合法n由实际数据识别并编排。 |
| 方法页可读性 | 以用途、分析输入/输出、去重配图及适配说明为主要入口；像SHAP页一样能辨认方法与结果、图的对应，但不能照抄其直接可接能力。来源、接口结构和完整证据可展开查看，原始Markdown保留完整事实与作者备注。无配图/无直连接口如实解释，不只呈现误导性的空链路。 |
| 状态与队列 | 来源签核、模板回放、作者确认和实际运行验证分开。CLI/网页按同一个workflow判定剩余动作，来源与模板不重复计数；已确认且覆盖完整退出待办，归档/删除/恢复后重算。不为清零改签核状态。 |
| 实际验收 | 检查数据/代码/预览链接与前端实际呈现；模板完成公开verify-template、换数据/规模/可移植检查与作者确认。方法笔记核对边界和代码验证范围后交作者确认；文字笔记不强制具备可执行流水线。机械/示例通过不扩大成统计、真实课题或科学有效性证明。 |
| 交付一致 | 记录检查范围、依据、未通过/未测项；规则变更同步正式Wiki与三处全局安装，共用同一库。更新不改变已确认的数据、算法、来源、作者区块和签核；若需实质改变，单独说明并询问。 |

SHAP和回归评估仅是同一验收标准的不同例子：前者的已声明输出表对应三个历史绘图模板；后者有两个绘图模板，但要另准备同源RGB/边缘表或选定指标与摘要，仍标需要适配。例子的图数、模型名和列名不是后续入库的固定要求。


单panel图样与可调用模板是可重叠的浏览视图，不是互斥的页面类型。已拆出的SHAP条形、蜂群、环形等合法单panel模板也属于图样；不能因其仍追溯到归档整图而遗漏。已有对应单panel来源时按明示覆盖只展示一次，缺独立来源页时直接链接现有模板记录，不为前端展示重新入库或生成待办。


### 入库验收的执行入口（2026-10-21 修复）

- 来源读取版本 `gallery_version` 与作者已签版本 `signedoff_version` 独立。网页签核记录当前来源版本；新版本反复 ingest 都保持待签核，刷新不能代替作者签核。来源在页面读取后又更新时先重新收录核对。历史已确认来源保留其原签核事实，不因迁移虚构新确认。
- `verify-template` 的成功记录绑定当前 code、spec、示例数据、接口列定义和 PNG/PDF/SVG 输出哈希。修改这些输入、替换输出或失败重跑均使旧回放失效，旧记录保留历史。未绑定哈希的旧回放不作为当前执行证据；先用原代码/原示例重新 verify，不改算法或伪造记录。回放环境与范围另记，不能证明所有依赖环境或科学有效。
- `mark-ready` 拒绝只有 preview 的模板；来源可选 ready 也须有效 layout 回放。方法确认核查用途、适用/不适用、输入、怎么做、代码状态、输出和知识关联检查；空骨架/TODO 仍由 agent 完善。有内容的文字方法可无代码/接口，明确无匹配理由即可，不为验收补算法。
- 方法、模板及来源正文都写“知识关联检查”：日期、查过的页面/范围、一方法多图与一图多方法判断、依据/限制、无匹配原因。机器核查该节和其他必需节不是空白/占位，并检查已声明关系结构；科学语义仍由 agent 核查，不把文字存在当成科学验证。
- 公开 `check-entry <id>` 查询当前缺项；核对完成后 `check-entry <id> --record` 保存 `acceptance.json` 和 Git 记录。确认入口也自动保存相同验收记录。记录内容指纹、已检查节及回放范围，不推进作者状态、不证明科学有效。实质更新后重新检查，作者区块、facts、标签/收藏与验收内容分开。
- `pending --json` 与网页共用 workflow，列出所有仍需 agent 的方法/模板/来源动作，包含真实缺项；默认 `pending` 为兼容旧用法仍只列来源 ID。处理待办优先 JSON，不遗漏方法或独立模板，不重复 scaffold、不为清零改签核。已有 ready 条目出现回放或验收内容变动时显示真实待核查动作，原签核事实保留。
- 图库与方法页共用明示覆盖分组：多个来源完整、双向复用同一模板时只显示一个图样，并保留每个来源链接。未知覆盖、非法重复覆盖及不同结构不合并；图样/函数两栏仍可重叠，SHAP 单panel不因整图来源归档而消失。
- 通用表格入口检查文件和必需列，具体函数另查其前提。类型、缺失、单位、实体/配对和科学含义必须由课题 agent 与具体方法核查；列名通过不等于数据有效。不得靠关闭结构检查兼容数据，也不自动转换单位、填补或改统计逻辑。

### 方法关系的模板优先（2026-10-22）

- 模板 ready 后，方法的 `figure_relations` 主记录指向可调用模板；来源 layout 只放在 evidence/正文溯源，不再作为主关系。
- 若方法关系仍指向 layout，而该 layout 已有 ready 覆盖模板，`lint` 报 ERROR；确认/推荐前改为模板关系，并保留 layout 证据。
- 方法声明输出与模板输入接口不一致时，关系写 `adaptable`；方法页在“接口结构匹配”旁另列“语义关联的模板（需适配）”，给出模板链接与适配动作。结构匹配栏只列真正消费声明输出的模板。
- 关系卡的状态显示目标页的有效 workflow（如“模板已就绪”），不把来源的 `pending_template` 当成模板未完成；原始状态只作详情。
- 归档/删除模板后重新审计关系；不因归档把 layout 关系恢复为主关系。

### 链条完整性与读取接口（2026-10-22）

- 方法页“接口结构匹配”必须显示结构匹配模板；若没有直接消费声明输出的模板，必须另列“语义关联的模板（需适配）”，不能只留“暂无”。
- 每个结构匹配/需适配模板都要标出实际读取的接口（如 `render-scatter-rgb`）；适配关系要在 `输出` 或 `知识关联检查` 正文列出这些接口与准备步骤。`lint` 对“adaptable 关系的模板读取接口未在正文说明”报 WARN。
- 结构匹配只按已声明接口计算；语义关联/需适配模板不是结构直连，不能把适配模板标成 direct，或据此宣称方法已能直接出图。
- 方法输出接口没有结构模板也没有语义模板关系时，`lint` 报 WARN；在 `知识关联检查` 写一行“无图原因：…”即消除。不为凑链条伪造接口。
- `direct` 只能指向非 draft 的模板，且模板读取的接口全部在方法 `outputs` 中；否则写 `adaptable` 或 `candidate`（lint 报 ERROR）。

### 证据持久化与删除边界（2026-10-22）

- `verify/` 下的回放回执与 PNG/PDF/SVG 输出是 ready 的执行证据，随 Wiki 提交进 git；不要加回 `.gitignore`。ready 条目缺 `acceptance.json` 视为验收过期，须重新 `check-entry --record`。
- 模板必须记录至少一个来源 `layouts`（lint ERROR）。删除归档来源时，若它是某个未归档模板的唯一出处，删除被拒绝；先处理该模板。
- 历史整图来源不出现在图库、网络或待办工作项中；待办“已归档”只读列出它们，可查看删除范围后永久删除，不提供打开或恢复（仅单 panel 口径）。
- 网页服务只接受本机地址访问，并拒绝跨站写请求；不要为外部访问放开。
