# LLM Wiki 模式（本地落地）

原文：https://gist.github.com/karpathy/442a6bf555914893e9891c11519de94f

这是可定制模式，不是认证标准，也不引入新的执行平台。原文的三层在本库对应：

| 原文层 | 本库落点 | 规则 |
|---|---|---|
| 不可变原始来源 | 上游来源快照（`sources_root`）、画廊、`recipes/*/source/`、`methods/*/source/`、`original_code/` | 只读保留原语言、原字节、SHA-256、来源/许可证；不复制成 Wiki 正文，不覆盖。 |
| 编译 Markdown | `知识库/**/*.md` | agent 写的用途、选择条件、输入/输出、步骤、限制、关系与证据；事实、矛盾、未知项都保留。 |
| schema / 规则 | `知识库/AGENTS.md`、本技能 `SKILL.md`、`references/` | 页面类型、frontmatter、状态、验收、关系与代码契约。 |

## 操作

- **ingest**：收录/更新来源。开源库经来源登记与适配器建 L0 目录，按主题分批升为 L1 配方（见 [来源与配方契约](sources-and-recipes.md)）；画廊复刻是来源之一。先找已有方法家族、模板、接口；新来源优先更新已有知识，不按“一来源一页面”新增同义方法。
- **query**：`find` / `show` 读 `catalog.jsonl` 与页面；查模板、配方、方法、接口、课题与关系时先读页面“适用/不适用/输入/输出/代码状态”，接口同名或图型相似不自动等于适用。方法库按受控 `tags` 领域 → 受控 `purposes` 用途浏览；词表与去重计数由后端 `GET /api/method-taxonomy` 统一派生，分类只用于发现，不当科学适用性门槛。
- **lint**：检查断链、frontmatter、状态/验收过期、重复分析家族、未声明实现、not_run 分支、关系结构、`index.md` 与 `catalog.jsonl` 是否过期。lint 通过不代表科学语义正确。

## 本地边界

- `index.md` 每页一行 `summary`，`catalog.jsonl` 每个条目一行，都由 `wiki.py save` 重建；`log.md` 只追加；不手改 facts/status/user/favorite。
- 方法家族、实现收据与推荐门槛见 `references/method-families.md`。方法入库先走四步：读目的与输入 → 查库语义去重（含分类判定：同实现补来源/新算法加分支/流程/技术资料/新分析目的才建家族）→ 提炼与验证 → 知识整合与确认。
- 跨来源去重按研究问题、输入语义、统计单位、估计目标和算法假设判断；同一算法不同包装是实现差异，参数变化是配置；不同算法同家族要比较，不抹平差异。自动 lint 只做结构检查，语义同义性由 agent 审查。
- 来源 panel、完整原图、`original_code/` 只放画廊；Markdown 只存路径/哈希/bbox/证据，不复制同字节图片。模板/方法资产可存代码、示例和真实回放；无回放时显示来源图并标“来源参考图／尚无回放”。
- 运行依赖与独立性只由资产根 `runtime.json` 和独立性收据描述；后端一处解析，API/前端/lint 共用。独立性 `verified` 与算法 `verified` 分开显示，互不代替。见 [最小运行清单](minimal-runtime.md)。
- 配方与模板可经 CLI 在 Wiki 专用环境实际运行并写收据（装包须作者按批次批准）；网页只展示代码与收据，不执行代码、不装包。缺包保留 `not_run` 和精确错误。
- 查询/课题中得到的可复用判断、失败模式和适配动作，先登记课题状态层 lesson 草稿（证据必填、同题合并、署名评审；accepted 须附作者决策记录），经正式 Wiki 评审后回填 `projects/` 或页面“使用记录”；不把对话当知识库。
- 不引入数据库、向量库、网页执行器或第二套 workflow；Obsidian/神经图谱只读浏览，不改变业务状态。

## 网页、删除与预览

- 网页服务只接受本机地址访问，并拒绝跨站写请求；不要为外部访问放开。
- 网页归档区与详情可先查看删除范围，再由作者明确确认永久删除 Wiki 页面及其专属资产；自动清理 agent 正文、元数据与布局中的关联，记录到 deletion-records，原始画廊保留。后端只允许删除 archived 条目并核对确认时的内容版本；他页作者备注引用须由作者先处理。agent 不因作者要求“加删除功能”就代删正式条目。
- 预览以实际存在的资源为准：模板有回放显示回放；没有回放时可显示来源配方的原样运行图或单 panel 来源缩略图，并标明“模板尚无回放”；配方显示最近一次通过的原样运行图；都没有时显示暂无预览，不以来源图冒充已验证模板。

## Obsidian 辅助阅读

- 只把知识库目录作为 vault；不把项目根、开发目录或画廊联接进 vault，不迁移业务页面或资产。
- Obsidian 用于阅读、搜索、反向链接、关系浏览和作者备注。作者直接编辑限 user 区块；签核、待办、确认、收藏/归档与删除继续走网页/CLI，不用插件另建 workflow。
- 不在 Obsidian 重命名、移动或删除正式条目（文件名就是业务 id）；不用属性面板编辑嵌套 YAML 或业务字段。`.obsidian/` 是本机配置，不进 Git。
- 搜索与图谱可排除 `verify`、`__pycache__` 等过程目录；这不改变 Git 规则，`verify/` 回放证据仍随 Wiki 提交。
- 神经图谱插件只读当前 vault，显示已有引用与原始状态；连线不等于 direct/适配关系、有效 workflow、执行或科学验证。插件不写页面、不运行代码、不联网。
